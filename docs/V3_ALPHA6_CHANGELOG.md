# V3.0-alpha6 Changelog

## 目标

本版重点不是继续堆功能，而是收紧制作中心的界面边界，并把“审计”升级成真正可用于发布决策和问题修复的工作台。

## 1. 制作中心界面边界

针对极窄屏、超长标题、超多页面和长 JSON 做了专门处理：

- 最低按 320px 视口进行压力回归；
- 顶部期刊标题最多显示 2–3 行，避免超长标题把操作区推离屏幕；
- 页面编辑标题最多显示两行；
- 页面列表、期刊列表统一使用省略与独立滚动区；
- “删除页”等操作按钮禁止被标题挤成竖排；
- 900px 以下期刊列表改为横向滚动，不再占用大量纵向空间；
- 620px 以下顶部操作区改为双列，340px 以下自动单列；
- textarea 有明确最小/最大高度，避免 JSON 编辑器无限撑开页面；
- dialog 使用 `100dvh` 边界，确保小屏弹窗不会越出视口；
- toast 在手机端改为顶部浮层，避免遮挡底部审计筛选与操作；
- 字符计数超过服务端边界时会标红；
- 制作中心最多允许 200 页，单页 blocks JSON 服务端上限 600KB。

## 2. 可操作的发布审计中心

制作中心新增独立“发布审计中心”，不再只输出命令行日志。

每条审计结果现在包含：

- 严重级别：阻断 / 警告 / 提示；
- 检查代码；
- 问题分类；
- 具体位置：元数据、页码、字段或资源路径；
- 修复建议；
- “定位”按钮；
- 资源问题的“复制路径”能力；
- 可发布度分数；
- TTS、媒体、页数等关键指标；
- 日常审计和严格发布前检查两种模式；
- 完整 HTML 审计报告入口。

修改内容后，制作中心会把既有审计结果标记为“已过期”，提示重新复检。

## 3. 审计范围扩展

alpha6 除了资源/TTS，还会检查：

- `issue.id` 与目录名是否一致；
- `draft / ready / published` 状态；
- 封面是否存在、是否为第一页、是否重复；
- 尾页是否存在、是否位于末页；
- 页面标题、导航标题、眉题是否缺失或过长；
- 重复导航标题；
- “请填写 / 待编辑 / TODO”等占位内容；
- 单个正文块是否过长；
- 空内容页；
- TOC 页码是否越界；
- `articleLink` 是否引用不存在的文章；
- 图片是否缺少 alt；
- 视频是否缺少 caption；
- HTTP 非安全文章链接；
- `assetSource` 是否越出项目路径；
- 媒体缺失、空文件、异常小文件、超大文件；
- TTS 缺页；
- 未引用媒体；
- 本期媒体总量。

若整个 `assetSource` 在 overlay 工作区不存在，不再重复输出几十条媒体缺失信息，只报告一个根因问题，降低审计噪声。

## 4. API 边界与错误可用性

制作中心服务端增加明确校验：

- 期名最多 40 字符；
- 本期主题最多 120 字符；
- 发布单位最多 120 字符；
- 页面标题 / navTitle / kicker 最多 120 字符；
- 最多 200 页；
- 单页 blocks JSON 最大 600KB。

边界错误返回 HTTP 400 和 `VALIDATION_ERROR`，不再把用户输入问题误报为服务器 500。

## 5. 新增制作中心浏览器回归

新增：

```bash
npm run test:studio-browser
```

自动在以下视口运行 Chromium：

- 320×740
- 390×844
- 768×1024
- 1366×768
- 1920×1080

测试数据使用 48 页和故意超长标题，验证：

- 无横向溢出；
- 表单控件不越界；
- 页面列表完整；
- 弹窗不越界；
- 审计结果正常渲染；
- “定位到第 18 页主标题”可用；
- “定位到本期主题”可用。

`npm run verify:v3` 已纳入这项测试。
