# V3.1-alpha7 制作看板 / 计划—页面闭环

## 1. Alpha7 解决什么问题

Alpha6 已经解决“先规划，再生成缺失页面骨架”。Alpha7 不再增加新的导入器或成刊字段，而是解决骨架生成后的制作闭环：

- 哪些计划页尚未建立；
- 哪些页面仍是“请填写…”占位骨架；
- 哪些页面已经有有效正文；
- 哪些页面已经明显充实；
- 哪些页面标题仍匹配计划，但栏目或页面类型已经漂移；
- 哪些正文页没有纳入整刊计划；
- 制作侧 `status` 是否与当前页面现状明显矛盾。

## 2. 不增加 Reader 运行时依赖

制作看板完全由两份既有数据现场派生：

1. `.v3-editorial-plans/<issueId>.json`；
2. 当前工作区中的 `issue.json` 页面。

Alpha7 不新增 `issue.json` 必填字段，也不会把 planId、制作画像、看板状态或正式门禁结果写入成刊。

## 3. 页面制作画像

每个计划目标页按本地确定性规则分为：

- `missing`：计划目标页不存在；
- `skeleton`：存在页面，但仍包含明显占位文字，或有效正文极少；
- `content`：已存在有效内容，但内容量/媒体信号尚未达到“充实”画像；
- `enriched`：正文量较高，或已经绑定媒体/文章，或有较丰富的信息卡片。

这里的“已充实”只表示**制作侧内容画像**，不等于审计通过，更不等于正式发布 READY。

## 4. 结构漂移

Alpha6 精确匹配使用：

- 目标标题；
- 页面类型；
- 栏目。

如果标题仍然对应，但类型或栏目变化，Alpha7 将它标记为“结构漂移”，而不是简单当成一个全新缺页。这样可以快速发现制作过程中手工调整导致的计划—页面偏差。

## 5. 未纳入计划页面

看板会列出没有被任何计划目标精确匹配或漂移关联的正文页，并提供直接定位。

这是一项制作提示，不会自动删除、移动或回写计划。

## 6. 状态建议

Alpha7 会根据页面现状给出 sidecar `status` 建议：

- 没有页面：`planned`；
- 已有页面但存在缺页、漂移或骨架：`in-progress`；
- 目标页全部存在且不再是占位骨架：`done`；
- `hold` 始终尊重人工暂缓，不参与自动建议覆盖。

用户必须显式点击“按页面现状更新计划状态”并确认，才会写入现有 sidecar `status` 字段。

该动作：

- 不写 `issue.status`；
- 不调用发布；
- 不生成正式门禁证据；
- 不将“已完成”解释为 V3.0.0 READY。

## 7. 看板筛选与定位

提供：

- 全部；
- 需处理；
- 骨架；
- 漂移；
- 已充实。

看板和“未纳入计划页面”都可以直接定位到 Studio 对应页面。

## 8. 正式发布边界

Alpha7 继续保持：

- `npm run verify:core` 的开发回归 PASS 只是代码质量证据；
- `npm run final:status` 才读取 V3.0.0 六项真实正式门禁证据；
- Safari 实机、第三期实材、历史媒体、部署/回滚和 HTTPS 完整性仍需各自真实完成。
