# 制作流程改进与验收（2026-09-08）

服务对象：个人或单位编辑组制作、发布期刊。

## 本次实现

| 环节 | 改进 | 使用方式 |
| --- | --- | --- |
| 开始制作 | 首页直接选择模板；选刊后显示四步制作入口 | 填入稿件 → 编辑版面 → 检查全刊 → 发布分享 |
| 内容导入 | 将导入内容移出“更多”菜单 | 顶部或第一步直接打开，复用现有文档解析、分页与一键成刊 |
| 日常保存 | 普通草稿直接保存，减少一次确认 | 顶部、工作区和 Ctrl/Cmd+S 行为统一；已发布稿保留修订确认 |
| 保存保护 | 禁止重复提交，保留请求期间的新编辑 | 新编辑继续显示为未保存，依赖保存的后续发布操作停止 |
| 多窗口编辑 | 刷新服务器状态不再覆盖编辑起点版本；冲突持续拦截 | 下载当前修改备份，或备份并载入最新版本后手动合并 |
| 内容核对 | 在发布中心直接确认并设为待发布 | 保存失败时不声称核对状态已提交，严格发布检查继续生效 |
| 问题修复 | 检查项显示修复建议和页面定位按钮 | 点击“去修改”定位页面或期刊信息 |
| 模板检查 | 统一使用“待补充”占位标记 | 所有默认模板正文页及封底都纳入严格发布检查 |
| 编辑稳定性 | 翻页不新增空字段，保存后刷新列表不再重开当前期刊 | 防止一键成刊被无实际内容变化的状态打断 |

默认模板仍为丹心红、知行蓝、青禾绿，每套八页，使用独立本地图片资源。

Edge 浏览器人工操作验收（全部使用可丢弃的本地测试期刊）：

1. 首页选择模板，创建八页期刊，显示四步入口。
2. 粘贴中文稿件，解析为一页，通过“一键成刊预览”生成目录、保存、日常检查及构建。
3. 在发布中心保存待发布状态，未替换的模板文字仍使发布按钮保持禁用。

5. 模拟第二窗口更新源稿，旧窗口保存被拒绝，当前修改和冲突提示保留。
6. 390 × 844 视口中四步入口两列展示，页面无横向溢出，引导区无内容裁切；桌面引导区亦无裁切。

这不是 Safari、微信内置浏览器或真实手机的兼容性认证。未操作线上期刊、正式发布或部署目录。

## 尚未通过的原有检查

1. GitHub `V3 checks` 在 `verify:v31` 失败：`001 当前内容与 TTS 基线不一致`。在本次开发前的基准提交 `2645529`，以及模板提交 `f6240af` 上均是同一错误。需要按第一期真实正文重新生成音频，并确认基线；不能仅改指纹使检查通过。
2. `npm run test:publication-share` 返回 HTTP 409：缺少 `release-v3/003` 正式发布包。这个测试依赖已有第三期发布产物，当前干净开发环境不具备该前置条件。应在独立测试目录建立可重复的完整发布夹具，再验证公开部署和分享。
3. 本地发布中心显示 PDF 导出缺少可执行 Chromium。本次验证了 ZIP 归档，未宣称 PDF 导出通过。正式部署环境需配置 Chromium 后验收 PDF 字体、分页与长文。

## 建议下一轮优先级

| 优先级 | 建议 | 验收目标 | 粗估开发量 |
| --- | --- | --- | --- |
| P0 | 修复第一期真实音频基线，建立独立发布/分享测试数据 | 干净拉取仓库后全量检查可重复运行；音频与正文一致 | 1–2 天，另计实际音频生成与校听 |
| P1 | 将导入弹窗分为常用选项与高级设置 | 常用流程仅需选择/粘贴稿件、确认分页、开始制作；高级参数按需展开 | 1–2 天 |
| P1 | 模板“逐项填写”模式 | 每页列出待替换文字、照片、署名，点击直达对应编辑项，并显示待办数量 | 2–3 天 |
| P1 | 增强 Word 图文导入及长文容量反馈 | 保留图片与图注关系；超限内容明确报错，禁止静默截断 | 3–5 天 |
| P1 | 简化手机管理视图和页码同步 | 小屏优先编辑当前页、保存、预览，页码与实际画布一致 | 2–3 天 |
| P2 | 单位常用素材与栏目预设 | 常用 logo、署名、栏目、字体一次配置，多期复用 | 2–3 天 |
| P2 | 收集编辑意见到页面 | 意见、处理状态与对应页面关联，避免反复截图沟通 | 3–5 天 |

以上为单人熟悉项目后的粗估，不含内容整理与真实设备校审。当前已有一键成刊、自动目录、草稿恢复、版本快照、媒体管理和发布向导，应优先整合入口与完善可靠性，再考虑多人协作、付费会员等平台化能力。
