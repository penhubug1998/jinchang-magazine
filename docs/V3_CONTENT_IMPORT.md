# V3 内容快速导入指南

## 1. 入口

启动制作中心：

```bash
npm run studio:v3
```

在顶部“内容”菜单选择 **快速导入**。Alpha13 提供四种入口：

1. 粘贴正文
2. 文件导入
3. 批量文章
4. 栏目骨架

## 2. 识别规则

### Markdown

- 第一个 `# 一级标题`：作为文章标题，不重复生成正文块。
- `##` ～ `######`：转换为 `paragraph / subhead`。
- `> 引用`：转换为 `quote`。
- `- / * / +` 列表：转换为 `cardline`。
- `1. / 1) / 1、`：转换为编号 `cardline`。
- 普通段落：转换为 `paragraph / body`。

### TXT / 粘贴纯文本

- 第一段如果较短且不像完整句子，会优先作为标题。
- 单独的短标题行会识别为小标题。
- `>`、`＞` 开头的内容识别为引用。
- 连续列表行识别为 `cardline`。
- 其他内容识别为正文。

### Word

`.docx` 会读取 Word 段落样式：

- Title / 标题 / Heading 1：优先识别文章标题。
- Heading：识别为小标题。
- Quote / 引用：识别为引用。
- Word 列表：识别为编号卡片。
- 普通段落：正文。

旧 `.doc` 在 macOS 使用系统 `textutil` 时主要按纯文本规则二次识别，因此复杂 Word 样式保留程度不如 `.docx`。正式制作建议优先使用 `.docx`。

## 3. 自动分页

导入解析完成后不会马上修改期刊，而是先显示分页预览。

常用密度：

- 520：较疏，页数更多，适合老年阅读与大字号。
- 760：标准推荐。
- 1000：较紧凑。
- 1250：高密度，只适合短句/小字号场景。

分页器会：

1. 先将超长正文按句子拆成较短段落；
2. 根据正文、引用、卡片、图片/视频的视觉权重累计；
3. 达到目标密度或单页 block 上限后换页；
4. 生成 `标题（1）`、`标题（2）`……导航标题。

自动分页只是制作建议，应用后仍建议使用“成刊预览”检查真实版面。

## 4. 粘贴正文

适用于临时材料、网页整理稿、AI 辅助整理稿：

1. 粘贴正文；
2. 选择自动 / Markdown / 纯文本；
3. 选择页面类型和栏目；
4. 点击解析；
5. 检查识别统计和分页预览；
6. 点击应用，页面插入在当前页之后、尾刊寄语之前。

应用动作会进入多级撤销、自动草稿和保存差异系统。

## 5. 文件与批量文章

支持：

```text
.docx .doc .md .markdown .txt .text
```

单文件不超过 12 MB。批量文章一次最多选择 30 个文件，每个文件独立形成一份识别结果和 1～N 页分页结果。

批量导入不会因为某一个文件“悄悄覆盖”另一个文件；全部结果会先显示在预览区，确认后统一应用。

## 6. 栏目骨架

“栏目骨架”用于新一期快速复用上一期结构。

复制范围：

- 页面类型
- 导航标题结构
- 栏目归属
- kicker/版式结构
- block 类型结构

不会复制：

- 历史正文文本
- 图片/视频路径
- 外部文章 articleId
- 旧目录跳转内容

支持：

- 追加栏目骨架；
- 替换当前正文区，但保留封面、目录、尾刊寄语。

## 7. 我的模板

当前页面可保存为“我的模板”。模板最多 50 个。

保存时主动清除：

- image.src
- video.src / poster
- articleLink.articleId
- toc.items

这是为了避免把上一期的历史媒体或文章引用带入新一期。

## 8. 发布前必须继续做什么

导入完成并不等于可以发布。推荐流程：

```text
导入 / 批量导入
  ↓
人工校对识别结果
  ↓
成刊预览
  ↓
检查长页与分页
  ↓
媒体 / TTS 补齐
  ↓
日常审计
  ↓
发布前检查
  ↓
release:check / publish:v3
```

任何导入造成的正文或页面顺序变化都可能让已有 TTS 基线过期，这是预期行为，不应通过跳过审计来规避。
