# V3.1-alpha6 整刊编排工作流

## 1. 为什么 Alpha6 不再做另一个“导入器”

V3 现有能力已经覆盖：

- Word / Markdown / TXT 快速导入；
- 批量文章；
- 栏目骨架；
- Fast Track；
- 单页模板；
- Alpha5 内容保留式智能套版。

剩余缺口是“整刊制作顺序和完成度”。因此 Alpha6 只做计划与编排，把“先想清楚要做哪些页”放在“真正生成/导入正文”之前。

## 2. Sidecar 与成刊隔离

整刊计划位于：

```text
.v3-editorial-plans/<issueId>.json
```

它不进入 `issue.json`。计划中只允许：

- 稿件标题；
- 栏目；
- 页面语义类型；
- 计划页数；
- 首选版式；
- 制作状态；
- 制作备注。

不允许保存正文、图片、视频、articleId 或其他 Reader 数据。

因此删除整个 `.v3-editorial-plans/` 目录不会改变已保存成刊的 Reader 表现。

## 3. 两种快速建计划方式

### 从当前期刊同步

适合已有一期半成品时建立“制作看板”。现有页面不会变化，正文页会转换为计划项并标记为“已完成”。

### 参考上一期栏目

适合新一期策划。只读取上一期栏目、页面类型、页数和结构特征，建立“待制作”计划。

它与“栏目骨架导入”的区别是：

- 编排台：先形成计划，不创建页面；
- 栏目骨架：直接创建页面结构。

## 4. 生成缺失页面

点击“生成缺失页面”时：

1. 重新计算计划目标页与当前期刊的匹配关系；
2. 跳过已存在页面；
3. 跳过 `hold` 计划；
4. 检查 200 页上限；
5. 用户确认后才创建；
6. 页面插入尾刊寄语之前；
7. 使用既有页面模板生成占位内容；
8. 按计划套用 Alpha5 版式；
9. 不写入计划备注/计划 ID；
10. 计划状态从“待制作”进入“制作中”。

生成的是制作骨架，不代表稿件已经完成。

## 5. 与正式发布的关系

Alpha6 编排台不会：

- 自动把计划状态映射成 `issue.status=ready/published`；
- 自动发布；
- 自动满足 Safari、第三期实材、媒体、部署或 HTTPS 正式门禁；
- 将开发 smoke 解释为 V3.0.0 正式证据。

正式发布状态继续只由 `npm run final:status` 及其真实证据绑定决定。
