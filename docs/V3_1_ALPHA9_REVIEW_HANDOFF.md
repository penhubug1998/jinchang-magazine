# V3.1-alpha9 校审轮次 / 交接签收

## 1. 目标

Alpha9 在 Alpha8 的内部校审问题闭环之后，增加制作侧“轮次交接”能力：记录第几轮校审、交给谁、当时有哪些必须清零的问题，以及内部签收/退回结果。

## 2. 数据隔离

交接记录保存到 `.v3-review-handoffs/<issueId>.json`。它不写入 `issue.json`、不修改 `issue.status`、Reader 不读取，也不产生 `final:status` 所需要的正式证据。

## 3. 问题快照

生成一轮交接时，系统会快照 Alpha8 校审单中所有尚未 `reviewed` 的问题。后续判断签收时，只认当前校审单中同一问题明确变成 `reviewed`；问题被删除、设为 `hold` 或自动 finding 消失，都不会自动视为解决。

## 4. 轮次状态

- `draft`：内部交接草稿；
- `handed_off`：已经交给下一位编辑/复核人；
- `accepted`：本轮快照问题全部明确复核后，由用户显式签收；
- `returned`：明确退回修改，可再次交接。

## 5. 内部交接摘要

每轮可生成/复制一份文本摘要，包含接收人、角色、快照问题与当前解决状态，并固定标注“内部制作交接 · 非正式发布证据”。

## 6. 正式发布边界

Alpha9 的 `accepted` 只表示制作侧交接完成。它不能改变 V3.0.0 六项正式发布门禁，也不能作为 Safari、第三期实材、正式部署或 HTTPS 线上完整性的替代证据。
